# 跨境包裹打包统计小工具 — 产品需求文档（PRD）

| 项目 | 内容 |
|------|------|
| 文档版本 | v1.0 |
| 更新日期 | 2026-10-26 |
| 产品名称 | 每日包裹打包统计助手（暂定） |
| 目标平台 | Web 网页端（PWA），优先适配手机浏览器，便于随时记录 |
| 目标用户 | 每天需要记录跨境包裹打包数量并核算收入的打包员、仓库人员或小卖家 |

---

## 1. 产品背景与目标

### 1.1 背景
用户每天需要记录自己打包的跨境包裹数量，目前为手工记录（纸笔或备忘录），无法快速：
- 知道“今天/本月一共打了多少件”；
- 知道“今天/本月收入是多少”；
- 回溯历史数据并与实际结算对账。

### 1.2 核心目标
做一款**极简、轻量、手机优先**的小工具，让用户在 3 步之内完成每日打包数量记录，并自动按 **1.5 元/件** 计算收入，支持历史查询、月度统计与导出对账。

### 1.3 成功指标
| 指标 | 定义 | 目标值（MVP） |
|------|------|--------------|
| 记录完成时长 | 打开首页 → 保存一条记录所需时间 | ≤ 10 秒 |
| 月度统计准确率 | 自动计算收入与手工核算一致的比例 | ≥ 99% |
| 周活跃率 | 每周至少记录 1 次的用户占比 | ≥ 80% |
| 数据完整性 | 有记录遗漏提醒后补录的比例 | ≥ 70% |

---

## 2. 用户画像

### 2.1 主要用户：打包员 / 仓库操作员
- 每天工作结束后需要快速记录当天打包件数；
- 对收入敏感，希望按件计费结果一目了然；
- 手机操作为主，希望界面大、步骤少、无需学习。

### 2.2 次要用户：小卖家 / 班组长
- 需要查看多人或多日汇总；
- 需要导出数据用于工资结算或对账（后续版本支持）。

---

## 3. 核心业务流程

```text
开始
  │
  ▼
选择日期（默认今天）
  │
  ▼
输入当天打包件数
  │
  ▼
系统自动计算收入 = 件数 × 1.5 元
  │
  ▼
保存记录
  │
  ▼
首页/统计页查看当日/当月汇总
```

## 4. 功能需求

### 4.1 每日记录（核心功能）

| 需求编号 | 用户故事 | 验收标准 |
|---------|---------|---------|
| F-001 | 作为打包员，我打开首页时默认显示今天的记录入口，方便我直接录入。 | 首页默认日期为当天；日期选择器可切换过去/未来 7 天内的日期。 |
| F-002 | 作为打包员，我输入打包件数后，能立即看到对应的收入金额。 | 件数输入框变化时，收入金额实时更新；公式为 `收入 = 件数 × 1.5 元`；显示保留 2 位小数。 |
| F-003 | 作为打包员，我可以为某天补录或修改记录。 | 同一天只能有一条记录；再次保存时覆盖旧记录并保留修改时间。 |
| F-004 | 作为打包员，我可以删除误填的记录。 | 删除需二次确认；删除后当月统计实时刷新。 |
| F-005 | 作为打包员，我可以给某天添加备注（如“加班”“请假”“SKU 多”）。 | 备注为非必填字段，字数限制 100 字。 |

### 4.2 统计看板

| 需求编号 | 用户故事 | 验收标准 |
|---------|---------|---------|
| F-006 | 作为打包员，我想知道今天/本月共打包多少件、收入多少。 | 首页顶部展示：今日件数、今日收入、本月累计件数、本月累计收入。 |
| F-007 | 作为打包员，我想了解自己的日均产出。 | 统计页展示：当月日均件数、日均收入、最高单日件数、最高单日收入。 |
| F-008 | 作为打包员，我想按月查看历史汇总。 | 支持按月份切换；展示该月总件数、总收入、工作天数、缺勤/未记录天数。 |

### 4.3 历史记录查询

| 需求编号 | 用户故事 | 验收标准 |
|---------|---------|---------|
| F-009 | 作为打包员，我想查看每一天的详细记录。 | 历史页以日历/列表形式展示；每条记录显示日期、件数、收入、备注。 |
| F-010 | 作为打包员，我想快速找到某一天的记录。 | 支持按日期范围筛选；支持按关键词搜索备注。 |

### 4.4 数据导出（MVP 可简化，后续优先）

| 需求编号 | 用户故事 | 验收标准 |
|---------|---------|---------|
| F-011 | 作为打包员或小卖家，我想导出月度数据用于对账。 | 支持导出当月数据为 CSV/Excel；字段包含：日期、件数、单价、收入、备注。 |

### 4.5 设置

| 需求编号 | 用户故事 | 验收标准 |
|---------|---------|---------|
| F-012 | 作为用户，我希望单价可以调整，以防以后涨价或不同岗位不同价。 | 设置页可修改“单件收入”，默认 1.5 元，范围 0.01–100 元；修改后历史记录收入按新单价重新计算。 |
| F-013 | 作为用户，我希望有每日提醒，避免忘记记录。 | 可选开启每日提醒（默认 21:00）；提醒文案可自定义。 |

## 5. 业务规则

1. **收入计算公式**：`收入 = 打包件数 × 单件收入`，单件收入默认 **1.5 元**。
2. **件数规则**：件数为大于等于 0 的整数；允许为 0，表示当天无产出或请假。
3. **记录唯一性**：每个自然日仅允许存在一条记录；重复保存视为修改。
4. **统计口径**：
   - “今日”指当前自然日 00:00–23:59；
   - “本月”指当前自然月 1 日至当月最后一日；
   - 未记录的日期不计入“工作天数”，但计入“未记录天数”。
5. **单价调整影响**：修改单价后，所有历史记录收入按新单价重新计算（因为收入是按件计酬的实时单价）。

## 6. 数据模型（MVP）

### 6.1 记录表（Record）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | string | 唯一标识 |
| date | string (YYYY-MM-DD) | 记录日期 |
| count | integer | 打包件数，≥ 0 |
| unitPrice | decimal | 单件收入，默认 1.50 |
| income | decimal | 收入，计算字段 = count × unitPrice |
| note | string | 备注，可选，≤ 100 字 |
| createdAt | timestamp | 创建时间 |
| updatedAt | timestamp | 最后修改时间 |

### 6.2 设置表（Settings）

| 字段 | 类型 | 说明 |
|------|------|------|
| unitPrice | decimal | 默认单件收入，默认 1.50 |
| reminderEnabled | boolean | 是否开启每日提醒 |
| reminderTime | time | 提醒时间，默认 21:00 |
| reminderText | string | 提醒文案 |

## 7. 界面与交互概述

### 7.1 首页（今日记录 + 统计卡片区）
- 顶部卡片：今日件数、今日收入、本月累计件数、本月累计收入。
- 中部输入区：日期选择、件数输入（大号数字键盘）、实时收入预览。
- 底部操作：保存、查看历史、设置。

### 7.2 历史页
- 默认展示当月列表，按日期倒序。
- 顶部月份切换器；支持滑动/点击切换月份。
- 每条记录可左滑编辑或删除。

### 7.3 统计页
- 当月总览：总件数、总收入、工作天数、日均件数、日均收入。
- 简单趋势图（可选）：近 7 天/30 天件数折线图或柱状图。
- 最佳单日高亮。

### 7.4 设置页
- 单件收入设置。
- 每日提醒开关与时间。
- 数据导出按钮。
- 关于/帮助。

## 8. 非功能性需求

| 类别 | 需求 |
|------|------|
| 性能 | 首页加载 ≤ 1 秒；保存记录 ≤ 300 ms。 |
| 可用性 | 手机优先；大按钮、大字体；无需登录即可使用（本地存储）。 |
| 可靠性 | 数据本地持久化，避免误删；支持手动备份/导出。 |
| 可访问性 | 输入框有明确标签；收入数字使用高对比色。 |
| 安全隐私 | 不上传用户数据至服务器；导出文件仅保存在本地。 |
| 离线能力 | 支持离线记录，联网后无需额外同步（若选择 PWA）。 |

## 9. MVP 范围与后续规划

### 9.1 MVP（第一版）
- 响应式 Web 页面，优先在手机浏览器中使用；
- 每日件数录入与自动收入计算；
- 首页今日/本月统计；
- 历史记录列表与按月份查看；
- 单件收入设置；
- 浏览器本地数据持久化。

## 10. 待确认问题

在正式开发前，建议与用户确认以下问题：

1. **PWA 深度**：是否需要“添加到主屏幕”“离线可用”等 PWA 特性，还是普通响应式网页即可？
2. **是否需要登录**：个人使用即可，还是需要多账号/班组长查看？
3. **数据存储位置**：浏览器本地存储（IndexedDB/LocalStorage）即可，还是需要云端备份？
4. **结算周期**：按自然月统计即可，还是按自定义结算周期（如每月 15 日）？
5. **是否有多种包裹类型/单价**：未来是否会出现不同 SKU 或岗位单价不同的情况？
6. **导出格式**：CSV 即可，还是需要 Excel 格式？
