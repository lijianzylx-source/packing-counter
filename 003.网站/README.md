# 每日包裹打包统计助手（Web 版）v1.1.0 · PC 版

按 [001.产品PRD/跨境包裹打包统计-PRD-v1.0.1.md](../001.产品PRD/跨境包裹打包统计-PRD-v1.0.1.md) + [v1.1.0 · PC 版](../001.产品PRD/跨境包裹打包统计-PRD-v1.1.0-PC版.md) 实现：**记录 + 统计 + 导出 + 账号登录**，并提供**自适应布局**——手机浏览器用移动版，桌面浏览器（≥1024px）自动切换为 PC 版。配色遵循 [002.设计/配色方案.md](../002.设计/配色方案.md)。

> 收入公式：`收入 = 打包件数 × 单件收入`（默认 **1.5 元/件**，可在设置中修改，改价后历史收入自动重算）。
> **账号在服务器，打包记录与设置仍留在浏览器本地**——账号用于身份识别，记录数据不上传。

## 1. 快速开始

### 方式 A：双击启动（推荐）
双击 **`启动服务.bat`**，它会检查 Node 环境、启动服务器并自动打开浏览器。**这个黑窗口要一直开着**，关掉窗口服务就停了。

### 方式 B：命令行
```bash
cd 003.网站
node server.js            # 默认 5173 端口
node server.js 8080       # 指定端口
node server.js --open     # 启动后自动打开浏览器
```

启动后控制台会打印两个地址：

```
  Local:      http://localhost:5173
  LAN:        http://192.168.43.87:5173   <- open this on your phone
```

- **电脑上用**：浏览器打开 `http://localhost:5173`，首次使用点「注册」。
- **手机上用**：手机与电脑连同一个 Wi-Fi，浏览器打开上面的 **LAN** 地址。
- **服务器地址可改**：登录页下方有「服务器地址」输入框，填错端口或换电脑时改这里，点「连接」即可（保存在本机）。

> ⚠️ **不要直接双击 `index.html`**。浏览器会拦截「本地文件」访问本机服务器（Chrome 的本地网络保护策略），页面底部会出现「在服务器上打开页面」按钮，点它即可跳到服务器地址；这是正常路径，不是故障。

### 常驻运行（后台 / 开机自启）

已为你配置好 **Windows 计划任务 `PackCounterServer`**，服务器会一直常驻：

| 能力 | 说明 |
|------|------|
| **开机/登录自启** | 登录 Windows 后自动启动服务（无需手动操作） |
| **崩溃自愈** | 进程意外退出后 **1 分钟内自动拉起**（实测杀掉后 35 秒恢复） |
| **不重复启动** | 端口 5173 已在监听时直接跳过，不会起第二个实例 |
| **静默运行** | 无黑窗口，不打扰日常使用 |

**查看状态 / 手动启停：**
```powershell
Get-ScheduledTask -TaskName "PackCounterServer"      # 看状态（Running=运行中）
Start-ScheduledTask -TaskName "PackCounterServer"    # 手动启动
Stop-ScheduledTask  -TaskName "PackCounterServer"    # 手动停止
```
**彻底取消（不想开机自启）：**
```powershell
schtasks /Delete /TN "PackCounterServer" /F
```

也可以随时双击 **`后台启动.bat`** 手动拉起一个后台实例（端口已占用时会提示「已在运行」并跳过）。

> ⚠️ `.bat` 脚本里**只能用英文/ASCII**，不要写中文——cmd 按系统代码页（GBK）解析批处理，UTF-8 中文会导致命令被拆散执行（已踩过一次）。

### 手机打不开？按顺序排查

| 检查 | 操作 | 预期 / 说明 |
|------|------|-----------|
| 1. 服务器在跑吗 | 双击 `查看访问地址.bat` | 显示 `Running (PID …)` 与**当前**局域网地址（会自动复制到剪贴板） |
| 2. **防火墙放行了吗** | **右键 `开放手机访问.bat` → 以管理员身份运行** | 列出两条新规则（TCP 5173 + node.exe） |
| 3. 手机和电脑同网吗 | 手机 Wi-Fi 与电脑 WLAN 同一网络 | IP 同网段（如都是 192.168.43.x） |
| 4. 路由器隔离设备吗 | 手机改连手机热点再试 | 路由器开了「AP 隔离 / 访客网络隔离」时手机访问不到电脑 |
| 5. 地址变了吗 | 电脑 IP 会随 Wi-Fi 变化 | 每次用 `查看访问地址.bat` 看当前地址 |

> **为什么必须用管理员权限**：Windows 防火墙默认拦截入站连接。服务器由计划任务在后台静默启动，**不会弹「允许访问」提示**，于是手机的请求被直接丢弃。手动加一条放行规则即可。

### 其他常见问题

| 现象 | 原因与处理 |
|------|-----------|
| 浏览器显示「无法访问此网站」 | **服务器没在运行**——确认启动服务器的窗口还开着；若窗口里有红色报错（多为端口被占用），按提示换端口：`node server.js 8080` |
| 页面能开但登录报「无法连接服务器」 | 登录页下方「服务器地址」填错或端口不一致，点「连接」重新测试；地址以服务器窗口打印的为准 |
| 命令行访问超时、浏览器正常 | 你开了代理/VPN（本次环境检测到 `127.0.0.1:10808`）。浏览器的 bypass 列表含 `localhost` 不受影响；命令行工具请加 `--noproxy` 或设 `NO_PROXY=localhost,127.0.0.1` |
| `localhost` 打不开但 `127.0.0.1` 可以 | 个别环境 hosts/代理对 `localhost` 处理异常，直接用 `http://127.0.0.1:5173` |
| 手机打不开 LAN 地址 | 手机与电脑不在同一网络，或路由器开启了「AP 隔离」；先在电脑上确认该地址能开 |

## 2. PC 版（桌面端）

**同一个网址**，窗口宽度 ≥1024px 自动变成 PC 布局，不需要切换、不需要另一份数据。

| 差异 | 移动端（<1024px） | PC 端（≥1024px） |
|------|------------------|-----------------|
| 导航 | 底部标签栏 | **左侧固定侧边栏**（品牌 + 导航 + 今日概览 + 账号条） |
| 顶栏 | 品牌 + 单价 | **当前视图名** + 单价 |
| 记录页 | 单列（概览在上、表单在下） | **左表单 + 右概览**双栏 |
| 历史页 | 卡片列表 | **五列对齐的表格**（日期/件数/收入/备注/操作） |
| 统计页 | 2 列指标卡 | **4 列指标卡** + 更高更宽的趋势图（绘图区限宽居中） |
| 设置页 | 单列 | **两栏** |

### 键盘快捷键（PC 端）

| 按键 | 作用 |
|------|------|
| `N` | 聚焦「打包件数」输入框 |
| `Ctrl / ⌘ + Enter` | 保存当天记录 |
| `1` `2` `3` `4` | 切换 记录 / 历史 / 统计 / 设置 |

> 输入框内打字不会触发这些快捷键。

### 怎么在电脑上打开

和手机一样：启动服务器后用电脑浏览器打开 `http://localhost:5173`（或 `http://127.0.0.1:5173`）。浏览器窗口拉宽到 1024px 以上即为 PC 布局。

## 5. 账号与接口

### 5.1 接口

| 方法 | 路径 | 说明 | 成功 | 失败 |
|------|------|------|------|------|
| POST | `/api/register` | 注册并签发令牌 | 201 `{token, user}` | 400 用户名/密码不合法、用户名已存在 |
| POST | `/api/login` | 登录并签发令牌 | 200 `{token, user}` | 401 账号或密码错误、429 锁定中 |
| POST | `/api/logout` | 作废当前令牌 | 200 | — |
| GET | `/api/me` | 用令牌换取当前用户 | 200 `{user}` | 401 令牌无效 |

请求体：`{"username": "...", "password": "..."}`；令牌通过 `Authorization: Bearer <token>` 携带。

### 5.2 安全实现

- 密码只存 **scrypt** 派生值 + 16 字节随机盐（`scrypt$N$r$p$salt$hash`），校验用常数时间比较；
- 「用户不存在」时也会执行一次哈希运算，避免用响应时间探测账号；
- 用户名连续 5 次密码错误 → 锁定 15 分钟；
- 令牌为 32 字节随机值，服务端可即时作废，30 天过期自动清理；
- 接口与静态响应带 `Content-Security-Policy`（`frame-ancestors 'none'`）、`X-Content-Type-Options`、`X-Frame-Options`；
- 账号文件 `data/users.json` 由服务器拦截，HTTP 访问返回 403；
- 接口开放跨源访问（`Access-Control-Allow-Origin: *`），以便手机/局域网与 `file://` 页面也能调用；因鉴权走 `Authorization` 头而非 Cookie，跨源无法读取他人数据。

### 5.3 数据存放

- **账号**：服务器 `003.网站/data/users.json`（含用户名与密码哈希）。
- **打包记录与设置**：浏览器 `localStorage`（`pkgstat.records.v1` / `pkgstat.settings.v1`），**不上传服务器**。
- **登录态**：`localStorage` 的 `pkgstat.auth.v1`（令牌 + 用户信息）。
- 清理浏览器数据会清除记录与登录态 → 请定期用「备份数据（JSON）」导出。

## 8. 已知限制与后续

| 项 | 说明 |
|----|------|
| 找回密码 | 无邮箱/手机验证，忘记密码需在服务器侧重置（v1.1 计划补） |
| 多设备 | 账号能跨设备登录，但**记录留在本机**，换设备看不到历史数据（v1.1 计划做云端同步） |
| 共用设备 | 同一浏览器只有一份本机数据，不按账号隔离 |
| 离线 | 服务器不可达时需手动点「离线使用」；离线模式下不做账号校验 |
| 提醒 | 依赖浏览器通知权限，页面需保持打开；移动端部分浏览器会拦截通知 |
| 部署 | 零依赖 Node 进程；对外提供服务需自行套 HTTPS 并妥善保管 `data/users.json` |
